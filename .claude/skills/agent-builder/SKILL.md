# Agent Builder

Ведёт пользователя от идеи до работающего, проверенного и безопасного агента. Пользователь учится строить агентов — поэтому на каждом этапе коротко объясняй **почему** принято решение, но не растягивай.

Полная теория — `agents/ГАЙД-ПО-АГЕНТАМ.md` в корне репозитория. Шаблоны — в `references/` этого скилла; читай нужный файл, когда дошёл до соответствующего этапа.

## Этап 0. Нужен ли вообще агент?

Агент = модель сама выбирает следующий шаг в цикле «думай → действуй → проверяй» до достижения цели. Это дороже и менее предсказуемо, чем скрипт. Выбери **самый простой** уровень, который решает задачу:

1. Один вызов модели с контекстом.
2. Цепочка шагов с проверками кодом (workflow).
3. Маршрутизация / параллелизация.
4. Оркестратор + исполнители (субагенты).
5. Генератор + оценщик.
6. Автономный агент с инструментами.

Если путь всегда одинаковый — честно скажи, что нужен скрипт/workflow, и сделай его. Агент оправдан, когда число шагов заранее неизвестно, нужно реагировать на промежуточные результаты, а итог можно проверить.

## Этап 1. Бриф

Заполни `references/agent-spec-template.md` вместе с пользователем. Не задавай все вопросы сразу: выведи что можешь из контекста, спроси только то, без чего нельзя. Обязательно зафиксировать:
- **Цель** одной фразой, в виде результата, а не шагов.
- **Definition of Done** — проверяемые признаки готовности.
- **Входы/выходы**, частота запуска, кто получает результат.
- **Границы:** что запрещено; какие действия только с подтверждением человека (деньги, цены, публикация, удаление, сообщения клиентам — всегда).
- **Что делать при застревании:** после N неудачных попыток остановиться и отчитаться.

## Этап 2. Дизайн

1. **Паттерн** из этапа 0 и форма реализации:
   - субагент Claude Code (`.claude/agents/<имя>.md`) — быстрый старт, работает внутри сессии;
   - скилл (`.claude/skills/<имя>/`) — переиспользуемое ноу-хау + скрипты;
   - Claude Agent SDK (`references/sdk-starter.md`) — автономный запуск из своего кода, по расписанию, на сервере.
2. **Инструменты** по `references/tool-design.md`: минимальный набор без пересечений, крупные операции, чтение отдельно от записи. Сначала проверь, что уже есть (MCP-серверы сессии, существующие скрипты проекта) — не дублируй.
3. **Права и ограничители:** белый список инструментов, режим разрешений, хуки `PreToolUse` для опасных действий, лимит шагов/бюджета.
4. **Память:** нужна ли между запусками (файл прогресса/заметок, лог решений). Для длинных задач — субагенты с чистым контекстом.
5. Покажи пользователю схему (блоки: миссия, инструкция, инструменты, цикл, память, ограничители, проверка) и получи согласие до сборки.

## Этап 3. Сборка

1. Системный промпт по `references/system-prompt-template.md`. Минимальный, но полный; объясняй причины правил; 1–3 показательных примера.
2. Инструменты: описания как для нового сотрудника, понятные ошибки, экономные ответы.
3. Ограничители кодом (хуки, валидация), а не только словами в промпте — промпт можно обойти, код нет.
4. Секреты только через переменные окружения/хранилище, никогда в файлах репозитория.
5. Первая версия работает в режиме **«только предлагать»**: ничего необратимого без человека.

## Этап 4. Тесты (evals) — это и есть «обучение»

По `references/evals-template.md`:
1. 5–10 реалистичных задач (включая сложные и «ловушки»: пустые данные, ошибка API, prompt injection во входных данных) с проверяемым ожидаемым результатом.
2. Прогони агента, сохрани транскрипты, читай их: где лишние шаги, где неверный выбор инструмента, где не проверил результат.
3. Исправляй **причину**: чаще всего — описание инструмента или формат его ответа, затем промпт. Добавляй правило только под наблюдённую ошибку.
4. Повторный прогон всего набора после каждого изменения. Каждый новый баг из боевой эксплуатации → новая задача в набор.

## Этап 5. Проверка безопасности

Пройди `references/safety-checklist.md` целиком и покажи пользователю результат. Если агент использует чужие скиллы/MCP/код — сначала раздел «Проверка стороннего кода». Официальные источники Anthropic (`github.com/anthropics/*`) — допустимы после просмотра; всё остальное — только после полной ручной проверки, без запуска до неё. Сомнение → не ставить, написать аналог самим.

## Этап 6. Запуск и сопровождение

- Автономию расширяй ступенями: предлагает → делает с подтверждением → делает сам в пределах лимитов. Переход — только после стабильных evals и согласия пользователя.
- Каждый запуск оставляет отчёт: что сделано, что проверено, что не получилось, что нужно от человека.
- Раз в период: разбор логов, новые задачи в evals, правки инструментов/промпта.

## Результат работы скилла

Создай папку агента (по умолчанию `agents/<имя>/`):
- `SPEC.md` — заполненная спецификация;
- сам агент (`.claude/agents/<имя>.md`, или скилл, или код на SDK);
- `evals/` — тестовые задачи и результаты прогонов;
- `SAFETY.md` — пройденный чек-лист;
- `README.md` — как запускать, как общаться, как улучшать.

В конце кратко объясни пользователю, какие решения приняты и почему, и предложи следующий шаг развития агента.
