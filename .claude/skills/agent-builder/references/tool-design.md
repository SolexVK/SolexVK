# Проектирование инструментов агента

Инструмент — это контракт между детерминированным кодом и недетерминированным агентом. Anthropic тратил на инструменты больше времени, чем на промпт, — и это окупается.

## Правила
1. **Мало и без пересечений.** Если человек не может однозначно сказать, какой из двух инструментов нужен, агент тоже не сможет.
2. **Крупные операции под задачу**, а не обёртка над каждым эндпоинтом API.
   - Плохо: `list_products`, `get_sales`, `get_stock` → агент сам склеивает и фильтрует.
   - Хорошо: `find_low_stock(days_of_cover_below=7)` → сразу нужный ответ.
3. **Имена с префиксом сервиса:** `wb_stock_find_low`, `tg_message_send`.
4. **Описание как для нового сотрудника:** что делает; когда использовать и когда нет; формат и пример параметров; ограничения; побочные эффекты.
5. **Однозначные параметры:** `user_id`, а не `user`; enum вместо свободного текста; абсолютные пути; даты в одном формате.
6. **Экономные ответы:** только нужные поля, человекочитаемые имена вместо ID, пагинация и фильтры с разумными значениями по умолчанию, режим `concise`/`detailed`.
7. **Понятные ошибки с подсказкой:** «date должен быть YYYY-MM-DD, получено 18.11.2026».
8. **Чтение и запись — разные инструменты.** Запись помечается как требующая подтверждения; при необходимости — режим `dry_run` (предпросмотр без действия).
9. **Идемпотентность записи:** повторный вызов не должен дублировать действие (ключ идемпотентности или проверка «уже сделано»).

## Шаблон описания инструмента
```
name: <service>_<resource>_<action>
description: |
  Что делает: ...
  Когда использовать: ...
  Когда НЕ использовать: ... (используй <другой инструмент>)
  Побочные эффекты: нет / изменяет <что>, требует подтверждения
parameters:
  <param>: <тип>, <формат>, <пример>, <по умолчанию>
returns: <поля>, <пример ответа>
errors: <типичные ошибки и что делать>
```

## Как проверить инструменты
1. Прогони evals, посчитай: число вызовов, ошибки параметров, лишние вызовы, токены.
2. Прочитай транскрипты: где агент путался — там правь описание или форму инструмента.
3. Повтори прогон.

## Внешние API и лимиты
- Перед работой с любым внешним API прочитай `agents/_shared/api-limits.md`; нет нужного API — найди официальные лимиты, допиши туда с источником.
- Лимиты соблюдаются **в коде инструмента** (пауза между запросами, обработка 429 по заголовкам, без повторов 4xx), а не в промпте.
- Предпочитай схему «скрипт собирает данные → агент анализирует файл»: меньше запросов, токен не попадает в контекст модели, агенту не нужны сетевые права.
