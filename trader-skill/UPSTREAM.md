## Результат проверки безопасности перед копированием

Прочитан весь код (11 скриптов Python, около 5,7 тыс. строк), все SKILL.md,
манифесты плагина, данные и тестовые фикстуры. Код оригинала не запускался.

- Только стандартная библиотека Python, внешних зависимостей нет.
- Сетевые запросы только к sec.gov, data.sec.gov, efts.sec.gov,
  disclosures-clerk.house.gov, finance.yahoo.com, stooq.com, api.openfigi.com.
  Единственный POST: api.openfigi.com (поиск тикера по CUSIP).
- Нет чтения ключей, домашней папки, конфигов Claude. Из переменных окружения
  читаются только SEC_USER_AGENT и OPENFIGI_API_KEY.
- Нет eval, exec, base64, скрытых символов. Единственный внешний процесс: pdftotext.
- Ни один скрипт не размещает ордера и не отправляет их куда-либо.
- Все записи идут в папку `trader/` проекта.

## Изменения относительно оригинала (2026-11-04)

Замечания аудита, которые были закрыты:

1. `trader-pelosi/ptr.py`: номер документа (`doc_id`) проверяется на «только
   цифры» и в скачанном индексе, и перед сборкой пути к PDF. Строки индекса с
   другим содержимым отбрасываются.
2. `trader-risk/check.py`: значение 0 для `max_position_pct`, `max_order_usd`,
   `max_orders_per_day` означает ноль (всё блокируется), а не «без лимита».
   Снять лимит можно только явным `null`.
3. `trader-risk/check.py`: дневной лимит и проверка дубликатов учитывают записи
   со статусом `approved`, а не только `placed`. Регистр поля `side` в журнале
   не имеет значения.
4. `trader-broker/ticket.py`: ответ «да» с любым тикером, кроме тикера этого
   ордера, отклоняется, даже если тикера нет в текущей пачке.
5. `common/net.py`: единая точка выхода в сеть для всех скриптов. Только https,
   белый список хостов, редирект на хост вне списка запрещён. Все пять
   скриптов с сетью переведены на неё.

Доработки под наш инструмент:

- `trader-tinvest/`: адаптер брокера Т-Банк (T-Invest API, REST). Песочница по
  умолчанию, боевой контур только при `"paper": false` и `TINVEST_LIVE=yes`.
  Котировки и портфель пишутся в формат пакета, ордера переводятся в лоты,
  размещается один одобренный ордер за запуск. Токены только из переменных
  окружения, никогда не печатаются.
- `trader-broker/ticket.py`: принимает «да» по-русски, отклоняет «да на все»,
  «да, но», «нет» и подобное; форматирует суммы в валюте из конфига
  (`"currency": "RUB"`); показывает тикет для брокера `tinvest`.
- `trader-risk/check.py`: формат тикера допускает цифры после первой буквы
  (X5, YDEX и другие бумаги Московской биржи).
- `tests/test_tinvest.py` и `tests/test_hardening.py`: офлайн-тесты всего
  перечисленного. `tests/test_repo.py` обновлён под новую структуру.
- README.md: раздел про этот форк и строка `/trader-tinvest`.

## Исследовательские скиллы под Московскую биржу (2026-11-05)

Пять скиллов оригинала читают только американские источники. Для каждого
добавлен параллельный скрипт под российский рынок, оригинальные скрипты
не тронуты:

- `trader-analyst/moex_facts.py`: фундаментальные показатели из T-Invest
  API (GetAssetFundamentals) в тот же `trader/metrics.json`, плюс дивиденды.
- `trader-screener/rules.moex.example.json`: правила под эти метрики. Сам
  `screen.py` не менялся.
- `trader-news/moex_news.py` и `moex_aliases.json`: ленты Финама, Мосбиржи,
  Интерфакса, РБК и Ведомостей, отбор по русским названиям бумаг, теги,
  показ один раз. Переиспользует `news.py` (время, дедупликация, состояние).
- `trader-copycat/moex_index.py`: состав и веса индексов из открытого API
  биржи (ISS) в `trader/targets.json`.
- `trader-pelosi`: российского аналога нет, остаётся для США.
- `common/net.py`: хосты iss.moex.com, www.moex.com и пять новостных.
- `tests/test_moex.py` и фикстуры `tests/fixtures/trader-moex/`.
- Бот: команды `/news`, `/metrics`, `/screen`, `/index`; задача `news` в
  планировщике (раз в час в торговые часы, только важное по своим бумагам).

Не менялось: остальные скрипты и SKILL.md оригинала, кроме сетевого вызова
и добавленных разделов «Московская биржа».
