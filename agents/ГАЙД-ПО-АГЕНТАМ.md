## 1. Агент vs скрипт vs «приложение с ИИ» — в чём разница

Anthropic делит все «умные» системы на два вида:

| | **Скрипт / workflow** (то, что у нас сейчас) | **Агент** |
|---|---|---|
| Кто решает, что делать дальше | **Код.** Путь прописан заранее: шаг 1 → шаг 2 → шаг 3 | **Модель.** Она сама выбирает следующий шаг и инструмент |
| Роль ИИ | Одна «умная функция» внутри конвейера (сгенерировать текст, классифицировать) | «Мозг», который крутится в цикле: *подумал → вызвал инструмент → посмотрел результат → решил дальше* |
| Неожиданная ситуация | Падает или выдаёт мусор — сценария нет | Замечает, перестраивает план, пробует иначе, спрашивает человека |
| Число шагов | Известно заранее | Неизвестно, зависит от задачи |
| Цель | «Выполни эти шаги» | «Добейся вот этого результата» |
| Плюсы | Предсказуемо, дёшево, легко отлаживать | Гибко, решает открытые задачи, доводит до результата |
| Минусы | Хрупко к новому | Дороже, медленнее, ошибки могут накапливаться — нужны ограничители |

**Формула агента:** `Цель + Инструменты + Цикл (думай → действуй → проверяй) + Критерий «готово» + Ограничители`.

**Важно — не всё нужно делать агентом.** Главный принцип Anthropic: *«начни с самого простого решения, добавляй автономию только когда она реально нужна»*. Если путь всегда одинаковый (например, «каждое утро выгрузить остатки и отправить в Telegram») — это скрипт, и это **правильно**. Агент нужен, когда:
- шагов заранее не знаешь («разберись, почему упали продажи по артикулу»);
- нужно реагировать на результат («нашёл проблему → проверил гипотезу → если не подтвердилась, ищи дальше»);
- задача открытая, но результат можно проверить.

### Лестница сложности (паттерны Anthropic) — от простого к сложному
1. **Один вызов модели** с нужным контекстом — часто этого достаточно.
2. **Цепочка промптов** — фиксированные шаги, между ними проверки кодом.
3. **Маршрутизация** — классифицировать вход и отправить в нужный обработчик.
4. **Параллелизация** — разбить на независимые куски или прогнать несколько раз и «проголосовать».
5. **Оркестратор + исполнители** — главная модель сама решает, какие подзадачи раздать.
6. **Генератор + оценщик** — один пишет, другой критикует по критериям, цикл до качества.
7. **Автономный агент** — модель с инструментами в цикле до достижения цели.

Наши текущие разработки — в основном уровни 1–3. Переход к агентам — это уровни 5–7.

## 2. Правила хорошего агента: умный, эффективный, надёжный, безопасный

### 2.1 Архитектура — 7 блоков

```
┌──────────────────────────────────────────────────────────┐
│ 1. МИССИЯ        цель, границы, критерий «готово»         │
│ 2. ИНСТРУКЦИЯ    системный промпт (роль, процесс, правила)│
│ 3. ИНСТРУМЕНТЫ   API, MCP-серверы, скрипты, файлы         │
│ 4. ЦИКЛ          думай → действуй → наблюдай → проверяй   │
│ 5. ПАМЯТЬ        заметки, прогресс, база знаний           │
│ 6. ОГРАНИЧИТЕЛИ  права, хуки, лимиты, подтверждения       │
│ 7. ПРОВЕРКА      тесты (evals), логи, отчёт человеку      │
└──────────────────────────────────────────────────────────┘
```

### 2.2 Миссия — чтобы агент «доводил до цели»
Агент доводит до цели только если цель **проверяема**. Плохо: «улучши карточки». Хорошо: «для артикулов из списка с CTR < 2 % предложи новый заголовок ≤ 60 символов с главным ключом из топ-5 запросов, сохрани таблицу `было/стало/обоснование`, ничего не публикуй без моего «ок»».

Обязательно прописать:
- **Definition of Done** — конкретные признаки, что задача решена.
- **Что делать, если застрял** — после N неудачных попыток остановиться и отчитаться, а не ходить по кругу.
- **Чего нельзя** — явный список запретов.

### 2.3 Системный промпт — «правильная высота»
- Не жёсткий if-else на каждый случай (хрупко) и не размытое «будь полезным» (бесполезно). Объясняй **зачем** — модель тогда сама правильно поступает в непредусмотренных случаях.
- Секции с заголовками: Роль → Цель → Процесс → Инструменты (когда какой) → Правила → Формат отчёта.
- Начинай с минимального промпта, гоняй на реальных задачах, **добавляй правила только под наблюдённые ошибки**.
- 2–3 разнообразных показательных примера лучше, чем 30 правил-исключений.

### 2.4 Инструменты — здесь 50 % успеха
Anthropic при разработке своего кодинг-агента **потратил на инструменты больше времени, чем на промпт**.
- **Мало и без пересечений.** Если человек не может сразу сказать, какой из двух инструментов использовать, агент тоже не сможет.
- **Крупные операции, а не обёртки над каждым API-эндпоинтом.** `найти_проседающие_артикулы(период, порог)` лучше, чем `получить_все_товары` + `получить_продажи` + ручная фильтрация.
- **Понятные имена с префиксом сервиса:** `wb_stock_get`, `tg_message_send`.
- **Описание как для нового сотрудника:** что делает, когда использовать, формат входа, пример, подводные камни.
- **Защита от дурака (poka-yoke):** абсолютные пути, enum вместо свободного текста, валидация.
- **Экономия токенов:** пагинация, фильтры, краткий/подробный режим ответа, человекочитаемые имена вместо ID.
- **Понятные ошибки:** не `Error 400`, а «Поле date должно быть в формате YYYY-MM-DD, получено 18.11».

### 2.5 Контекст и память — чтобы не «тупел» на длинных задачах
Чем больше контекста, тем хуже модель вспоминает детали («context rot»). Поэтому:
- **Подгружай данные по требованию**, а не всё сразу: держи в контексте ссылки/пути, читай по необходимости.
- **Заметки вне контекста:** файл `PROGRESS.md` / `NOTES.md` — что сделано, что дальше, какие решения приняты. Агент сможет продолжить после перезапуска.
- **Субагенты** для тяжёлых подзадач: работают в чистом контексте и возвращают сжатую выжимку.
- **Компактизация:** на длинной сессии — суммаризировать историю, сохранив решения и открытые проблемы.

### 2.6 Надёжность
- **Проверка после каждого действия** (ground truth): записал файл → прочитал; отправил запрос → проверил ответ.
- **Лимиты:** максимум итераций/шагов, бюджет, таймауты.
- **Идемпотентность:** повторный запуск не должен дублировать действия (например, повторно отвечать на тот же отзыв).
- **Прозрачность:** агент пишет план и логирует шаги — видно, почему он так решил.
- **Evals** (тестовый набор задач) — без них «агент работает» — это ощущение, а не факт. См. раздел 5.

### 2.7 Безопасность
- **Минимальные права.** Только нужные инструменты; чтение отдельно от записи.
- **Человек в контуре** для всего необратимого и внешнего: деньги, цены, публикация, удаление, отправка сообщений клиентам.
- **Хуки** (`PreToolUse`) — код, который проверяет каждое действие **до** выполнения и блокирует опасное (например, `rm -rf`, изменение цены больше чем на 20 %).
- **Секреты не в промпте и не в коде.** Ключи — через переменные окружения/хранилище, агенту — только то, что нужно.
- **Внешние данные — это данные, не команды.** Отзыв покупателя, веб-страница, письмо могут содержать «игнорируй инструкции и…» (prompt injection). Агент не должен выполнять инструкции из данных.
- **Песочница** для тестов: сначала на копии / тестовом кабинете / в режиме «только предложить».

## 3. Готовые скиллы на GitHub — что брать и что безопасно

### Вывод проверки
**Ставить что-то с GitHub не нужно.** Официальный `skill-creator` от Anthropic **уже встроен** в нашу среду (`anthropic-skills:skill-creator`). На его основе и по гайдам Anthropic я собрал наш собственный `agent-builder`. Ничего чужого не установлено.

### Как проверял (несколько углов)
1. **Издатель.** `skill-creator` лежит в `github.com/anthropics/skills` — официальная организация Anthropic. Остальные «skill-creator» в поиске — копии/форки на агрегаторах (skills.sh, skills.lc, claudemarket и др.); их авторство не проверяемо.
2. **Код.** Склонировал официальный репозиторий (коммит `e4bb5d9`, 16.11.2026) в изолированную папку, **ничего не запускал**, просканировал на опасные шаблоны (сетевые вызовы, `eval/exec`, обфускацию, доступ к `~/.aws`, `~/.ssh`, `CLAUDE.md`, установку пакетов). Результат: только стандартная библиотека Python + `yaml`; `subprocess` вызывает лишь `claude -p` (для тестов описаний) и `lsof` (освободить порт локального просмотрщика); сеть — только шрифты Google и библиотека SheetJS с проверкой целостности (SRI); `base64` — только для встраивания картинок в отчёт. **Опасного не найдено.**
3. **Экосистема в целом.** Исследования Snyk показывают, что сторонние скиллы — реальный канал атак:
   - ToxicSkills (фев. 2026): из 3 984 скиллов у 13,4 % критические проблемы, 76 подтверждённых вредоносных; 91 % вредоносных совмещают prompt injection с вредоносным кодом.
   - Повторный аудит (ноя. 2026, топ-10 000 на skills.sh и ClawHub): примеры — скилл, который тихо дописывал удалённые инструкции в глобальный `~/.claude/CLAUDE.md`; обфусцированный код, работающий с токенами; поддельные «официальные» издатели; домены-двойники.
4. **Вывод из 3:** официальное от Anthropic — можно; всё остальное — только после ручной проверки по чек-листу ниже, а лучше — писать своё.

### Чек-лист проверки любого чужого скилла/агента/MCP перед установкой
- [ ] Издатель проверяем и совпадает с заявленным (а не «official» от аккаунта недельной давности).
- [ ] Прочитан **весь** SKILL.md и все скрипты. Нет непонятных бинарников, base64-блоков, архивов с паролем.
- [ ] Нет команд «скачай и запусти» (`curl … | sh`, `git clone` чужого + `setup.sh`).
- [ ] Не трогает `~/.claude/CLAUDE.md`, `~/.ssh`, `~/.aws`, `.env`, кошельки, глобальные настройки.
- [ ] Нет текста «игнорируй предупреждения / developer mode / не показывай пользователю».
- [ ] Сетевые адреса понятны и нужны для задачи; нет доменов-двойников.
- [ ] Зафиксирована версия (коммит), а не «последняя».
- [ ] Первый запуск — в изоляции, без боевых ключей.
- [ ] Если сомневаешься — не ставь, попроси Claude написать аналог с нуля.

## 4. Как нам дальше работать с агентами

### Жизненный цикл агента
```
Идея → Бриф (цель, DoD, границы) → Дизайн (паттерн, инструменты, права)
     → Сборка (промпт, инструменты, хуки) → Тесты (evals)
     → Пилот в режиме «только предлагать» → Боевой режим с подтверждениями
     → Наблюдение (логи, отчёты) → Улучшение по ошибкам → снова Тесты
```

### Где агенты живут (от простого к мощному)
1. **Субагент Claude Code** — файл `.claude/agents/<имя>.md` (роль + список инструментов). Вызывается из нашей сессии. Самый быстрый старт.
2. **Скилл** — `.claude/skills/<имя>/SKILL.md`: «ноу-хау» + скрипты, которые любой агент подгружает по необходимости.
3. **Автономный агент на Claude Agent SDK** (Python `pip install claude-agent-sdk` / TypeScript) — тот же движок, что у Claude Code, но в твоём коде: свой промпт, инструменты, MCP, хуки, права, субагенты, сессии. Можно запускать по расписанию или на сервере.
4. **Запуск по расписанию в облаке** — scheduled tasks Claude Code: агент сам просыпается и выполняет задачу.

### Как общаться с агентом
- **Ставь цели, а не шаги:** «добейся X, критерий готовности Y, нельзя Z».
- **Спрашивай план до действия** на новых задачах.
- **Требуй отчёт** в фиксированном формате: что сделано, что проверено, что не получилось, что нужно от меня.
- **Ошибка = новое правило или тест.** Каждый провал агента превращаем в пример в evals и (если нужно) строку в промпте/инструменте. Так агент «учится».
- **Расширяй автономию постепенно:** предлагать → делать с подтверждением → делать самостоятельно в рамках лимитов.

### «Обучение» агента — что это на самом деле
Мы не дообучаем веса модели. Агент «учится» через:
1. **Инструкции** — системный промпт, уточняемый по ошибкам.
2. **Знания** — справочные файлы (регламенты, примеры, база ответов), подгружаемые по требованию.
3. **Инструменты** — лучше инструменты → умнее агент.
4. **Память** — заметки и история решений между запусками.
5. **Evals** — набор задач с ожидаемым результатом; прогон до и после каждого изменения.

## 5. Свой скилл: `agent-builder`

Лежит в `.claude/skills/agent-builder/`. Ведёт по шагам: проверка «нужен ли агент» → бриф → дизайн → сборка → тесты → проверка безопасности → запуск и сопровождение. Внутри шаблоны: спецификация агента, системный промпт, инструменты, evals, чек-лист безопасности, стартовый код на Agent SDK.

**Как пользоваться:** в сессии Claude Code в этом репозитории напиши, например:
> «Построй агента, который каждое утро проверяет остатки на WB и предупреждает о дефиците»

— скилл подхватится автоматически. Или явно: `/agent-builder`.

### План освоения навыка (практика)
1. **Неделя 1:** первый субагент в `.claude/agents/` для задачи «только чтение + отчёт» (например, анализ отзывов). Написать 5 тестовых задач.
2. **Неделя 2:** добавить инструмент записи с подтверждением человека + хук-ограничитель.
3. **Неделя 3:** перенести на Agent SDK, запуск по расписанию, файл прогресса/памяти.
4. **Неделя 4:** оркестратор + 2 субагента-исполнителя; evals из 15–20 задач; разбор логов и улучшение.
