# Лимиты внешних API — правила для всех агентов и инструментов

Любой инструмент, обращающийся к API ниже, **обязан** соблюдать эти правила в коде (а не полагаться на промпт).
Дата сбора: 18.11.2026. Лимиты меняются — при сомнении сверяться с источником.

## Wildberries Seller API

### Первоисточник у нас
Официальный снимок страницы WB «Общая информация / лимиты» — `SolexVK/wb-headless`, ветка `claude/wildberries-tools`:
`docs/wb-api/limits.md` (+ сводка `docs/wb-api/README.md`). Снимок обновляется еженедельно (GitHub Actions `wb-docs-refresh.yml`).
Там же готовый клиент с этими правилами — `lib/wbClient.js` (token bucket на категорию, `X-Ratelimit-*`, без ретраев 4xx).
Правило оттуда: **перед использованием нового метода читать его страницу и брать его собственный лимит** — он часто строже базового.

### Лимиты по типу токена (на аккаунт, период 1 минута, token bucket)
| Тип токена | Лимит | Интервал | Всплеск |
|---|---|---|---|
| Персональный | 300/мин | 200 мс | 20 |
| Сервисный | 300/мин | 200 мс | 20 |
| Базовый | 150/мин | 200 мс | 10 |
| Тестовый | 150/мин | 200 мс | 10 |

- **Запрос с ответом 4xx считается как 10 запросов** (официально, пример — категория «Маркетплейс»). 4xx не повторяем.
- Тип токена — по payload JWT (декодировать локально, не во внешних сервисах): `acc` 1 — базовый, 2 — тестовый, 3 — персональный (`for: self`), 4 — сервисный.
- ⚠️ **Персональный токен нельзя использовать в облачных сервисах и передавать третьим лицам** (официально). Для облачных агентов — отдельный токен подходящего типа с минимальными категориями.
- Отдельные методы строже: напр. `seller-info` у базового токена — 1 запрос в 24 ч, новости — 1 в час; `/ping` — максимум 3 запроса за 30 с.

### Общие правила (все категории)
- Превышение лимита → ответ **429**.
- В ответе 429 заголовок **`X-Ratelimit-Retry`** — через сколько секунд можно повторить. Повтор раньше → снова 429. Экспоненциальный бэкофф не нужен: ждать ровно `X-Ratelimit-Retry`.
- **`X-Ratelimit-Remaining`** (во всех ответах, кроме 429) — сколько запросов можно отправить сразу. **`X-Ratelimit-Limit`** — размер всплеска, **`X-Ratelimit-Reset`** — за сколько секунд он восстанавливается.
- Пример 429 из документации: `X-Ratelimit-Retry: 2`, `X-Ratelimit-Reset: 29`, `X-Ratelimit-Limit: 10`.
- Источник: [WB API — общая информация](https://dev.wildberries.ru/en/docs/openapi/api-information)

### «Вопросы и отзывы» (`feedbacks-api.wildberries.ru`)
- **1 запрос в секунду** на все методы вопросов и отзывов вместе.
- **Больше 3 запросов в секунду → блокировка на 60 секунд.**
- `GET /api/v1/feedbacks`: `take` ≤ **5 000**, `skip` ≤ **199 990**.
- Для вопросов `take + skip` ≤ 10 000; для отзывов такое ограничение в найденных источниках не описано — не полагаться, проверить на практике.
- Источники: [WB API — Customer Communication](https://dev.wildberries.ru/en/docs/openapi/user-communication), [openapi.wb.ru — Feedbacks and Questions](https://openapi.wb.ru/feedbacks-questions/api/en/)

### Не подтверждено официально (учитывать осторожно)
- «Каждый ответ 4xx засчитывается как 10 обычных запросов» — заявлено в [neurounit.ai](https://neurounit.ai/blog/api-wildberries-dokumentaciya/), в официальной документации не найдено. Практический вывод всё равно верный: **не повторять 401/403/400** — они повтором не лечатся.

### Как реализовано у нас
1. Пауза **≥ 1,1 с** между любыми запросами к `feedbacks-api` (запас к лимиту 1/с).
2. Запросы строго последовательно, без параллельности.
3. На 429 — ждать `X-Ratelimit-Retry` (нет заголовка — 60 с), не более 3 повторов.
4. Если `X-Ratelimit-Remaining` = 0 — ждать `X-Ratelimit-Reset` перед следующим запросом.
5. 400/401/403 — сразу стоп с понятной ошибкой, без повторов.
6. Сетевые сбои/5xx — до 3 повторов с паузой.
7. Меньше запросов — лучше: одна выгрузка истории на запуск, агент анализирует файл, а не ходит в API сам.

## MPStats (`mpstats.io`)
- У токена **дневной лимит запросов**. Ответ 429 с текстом «Превышен лимит запросов за <дата>» — дневной лимит: **повтором не лечится, остановить работу** и сказать пользователю подождать до следующих суток или поднять тариф. Не выдавать это за «нет данных».
- 429 без «лимит» в тексте и 5xx — временные, их можно повторить с бэкоффом.
- 401/403 — проверить `MPSTATS_TOKEN` и доступ к `mpstats.io`.
- Экономить лимит: опрашивать только нужные товары, а не весь каталог.
- Источник: наши правила из репозитория `SolexVK/wb-headless` — `lib/mpstats.js`, `report-stock.js`, `REPORTS.md`, `.claude/skills/wb-niche-analysis/references/mpstats.md`.
